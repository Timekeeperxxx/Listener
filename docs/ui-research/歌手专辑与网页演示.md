# 歌手、专辑与歌词交互更新

> 本文记录 0.2.3 时的实现。歌手与专辑部分已在 0.2.4 改为 QQ 线上乐库，包含真实介绍、头像和完整曲目，不再按已读取的收藏聚合。当前实现、接口验证和本机更新结果见 [0.2.4 更新说明](../releases/0.2.4.md)。HTML 的歌手、专辑和搜索现在读取线上公开元数据；播放、歌词及个人歌单仍为明确的演示交互。

日期：2026-11-04。网页入口：`http://127.0.0.1:4173/demo.html`。

## 1. Root Cause：需求与原因

- 原界面只能浏览歌单和歌曲，歌手、专辑名称无法继续打开。
- 歌词页的封面与歌曲信息在主布局中，控制区则单独固定在窗口底部；窗口变高后，两部分间距随之拉大。
- 展开、关闭歌词页时直接切换视图，没有过渡。
- AMLL 默认恢复自动对齐时，要求当前播放行已经处于渲染范围内。手动滚动很远后，这个条件可能一直不满足，导致鼠标移开后仍停留在浏览位置。

## 2. Modified Scope：改动范围

- `src/lib/catalog.ts`：从已读取的歌曲生成歌手与专辑索引，按歌曲 `mid` 去重，分别保留合唱歌曲的歌手入口。
- `src/stores/library.ts`：复用已经读取的收藏、歌单、搜索、历史数据；增加目录导航及返回。退出账户清空目录；取消后的请求不能重新填充目录。不增加 QQ 网络请求。
- `src/components/CatalogView.vue`：歌手列表、歌手概览/歌曲/专辑、专辑详情、相关专辑和筛选。
- `src/components/TrackList.vue`：歌手与专辑名称可点击，并阻止事件继续触发整行播放；专辑详情采用精简列。
- `src/components/PlayerDock.vue`、`LyricsView.vue`、`App.vue`、`src/style.css`：把歌词页封面、歌名、进度与控制区排成同一纵向组合；音乐库保留底栏。切换内容页回到顶部，关闭歌词保留底层页面。
- 歌词页使用独立覆盖层和 Vue `Transition`，展开 460ms、收起 340ms，主要动画属性是 `transform` 与 `opacity`；遵循现有系统减少动态效果规则。离场时继续使用覆盖层自己的样式，避免控制区提前跳回底栏位置。
- `SyncedLyrics.vue`：捕获手动滚动及鼠标移入、移出。离开后至少等待 800ms，并等待下一句的时间到达，再调用 AMLL 公共 `resetScroll` 接口，恢复原有歌词对齐位置（视口约 42% 处）。不跳转音频进度。最后一句没有后续歌词时，延时后对齐最后一句。
- 重新移入或继续滚动会取消本次回中；暂停、隐藏或卸载也会取消。通过现有动画帧检查条件，不增加持续计时器。
- `demo.html`、`src/demo/`、`vite.demo.config.ts`：独立 HTML 演示入口和构建。演示使用 6 位歌手、11 张专辑的示例资料，播放状态为界面模拟；歌词为原创排版示例。图片本地加载，来源记录于 `src/demo/asset-sources.json`。

## 3. Failure Policy：失败处理

正式入口继续使用原有 QQ 接口，保留登录、请求和持久化错误。网页演示通过独立入口显式安装内存数据，页面标注“网页演示”；不连接真实账户，不读取钥匙串，不下载或播放真实 QQ 音频。网页中不支持的账户和下载操作显示明确错误。

## 4. Added Defensive Branches：新增分支依据

- 缺少专辑名时不生成虚构专辑；缺少发行日期、简介或头像资料时，只显示已有的信息。歌手图片沿用该歌手歌曲封面，属于展示占位，不冒充真实肖像。
- 未找到歌手或专辑时显示空状态；筛选无匹配时显示无结果。
- 同名专辑包含署名歌手作为索引的一部分，避免把不同歌手的同名作品混在一起。
- 重复打开当前目录页不重复压入返回记录；导航取消旧请求并清除加载标记。退出账户清空全部目录记录。
- 回中只处理播放中、可见且发生过手动浏览的歌词；没有下一句是最后一句的有效情况。所有取消条件清除同一个待回中状态。
- 滚动位置的 DOM 引用在组件挂载前可能不存在，等待视图更新后仅在已挂载时复位。
- 歌词外层使用 `overflow: clip` 防止整个场景被滚动；保留 `overflow: hidden` 声明供不识别该 CSS 属性的 WebView 使用。
- 未增加网络重试、认证兜底、静默吞错或失败后的默认成功状态。

## 5. Explicit Non-Changes：边界与限制

尚未接入 QQ 歌手详情或完整专辑曲库接口。正式页面的“资料库中的歌曲”“已收录专辑”只表示本次已经读取的内容，不能当作歌手全部作品。现有 Track 数据没有歌手和专辑 ID，目录目前按展示名聚合；不同署名的合唱歌曲可能分在不同专辑条目中。

没有更改 QQ 认证、下载格式、播放源与持久化；没有把示例数据当作请求失败后的备用结果。示例图片与数据不进入常规 macOS 前端构建。本次没有重新安装或发布 macOS 应用，也没有发布外网网站。

## 6. Verification：验证

- 57 项测试通过，新增覆盖同名专辑、合唱署名、缺失元数据、目录返回、过期请求、退出账户以及延时回中、移入取消和暂停/隐藏取消。
- `npm run build` 和 `npm run build:demo` 通过，包含 TypeScript 检查；检查了常规 `dist` 不含演示头像及封面图片。
- 本地演示入口返回 HTTP 200。
- 网页实际点击验证歌手→专辑→返回歌手，内容页滚动位置回到 0，当前播放不因打开资料而改变。
- 浏览器实际记录展开动画 460ms/320ms，收起动画 340ms/300ms；连续 4 次快捷键切换后只有一个歌词覆盖层和一组控制区。
- 检查默认 1280×720 与 1710×1100 大窗口。封面、歌名、进度和控制区保持一组布局，没有原来的大块分离留白。
- 最终预览已恢复默认窗口尺寸并保留页面；浏览器控制台未记录错误或警告。最终画面：`artifacts/catalog-demo/lyrics-final.jpg`。
- 真实滚轮事件将当前播放行滚出视野，记录的中心位置从歌词视口约 -23% 恢复到约 42%，整个歌词场景 `scrollTop` 保持 0。精确的 800ms 条件与取消规则由自动化测试验证；没有以该观察测量 GPU 实际呈现帧率。
- 未进行本次 macOS 安装包运行、旧版本 WebView 或手机浏览器验证。

运行演示：`npm run demo`。静态演示构建：`npm run build:demo`，输出到 `demo-dist/`。查看页面需通过 HTTP 服务打开 HTML。

截图和运行记录保存在 `artifacts/catalog-demo/`。

示例图片与歌曲资料分别来自 QQ 音乐公开图片服务及 Apple 的公开目录接口，具体原始地址见 [素材来源记录](../../src/demo/asset-sources.json)。这些文件只用于本地界面演示。
