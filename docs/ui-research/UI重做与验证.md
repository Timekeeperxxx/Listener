# Listener UI 重做与验证

日期：2026-11-04。应用已重新构建并在本机运行。

## 1. 问题与原因

原界面的歌曲文字偏小、颜色偏淡，介绍文案和装饰占据了较多空间；歌词页沿用了浏览页面的框架。此次根据研究文档，以及用户追加的字体、顶部导航、封面位置和播放进度条要求重新整理。

最终采用接近 YesPlayMusic 的音乐库布局：顶部导航、居中内容区、收藏与最近播放、封面歌单网格。歌词页使用独立的完整窗口布局。

## 3. 失败策略

最近播放读取失败显示实际错误，不将失败表现为空记录或成功状态。歌词数据的错误和警告继续显示；用户要求删除的是日常介绍与技术标签。

暂停时使用 AMLL 的 `playing` 状态停止歌词演出，保留可见页面的布局更新，解决初次打开时没有绘制的问题。离开歌词页会销毁组件；隐藏或最小化窗口时通过既有可见性控制关闭渲染。

## 4. 新增边界判断

- 最近播放请求校验账户代次：退出账户后返回的旧数据不会重新填入页面。
- 最近播放请求的 `catch` 写入可见错误状态。
- 只有已连接账户时读取最近播放；收藏入口根据实际是否存在收藏歌单决定显示与操作。
- 译文默认显示，音译默认隐藏，是界面初始选项；切换仅影响呈现，不修改原始歌词。
- 系统“减少动态效果”变化时更新动画选项，并在组件销毁时移除监听。

没有增加推测性重试、兼容分支或静默回退。

## 5. 范围控制

本轮手工改动集中在界面、最近播放展示与相应测试。UI 实测未执行 QQ 歌单增删或收藏写操作。工作区已有的其他功能继续使用当前实现。

浏览器的长标题、列表和歌词测试使用独立测试页面中的临时数据；原生窗口截图与播放验证使用真实账户和歌曲。测试数据没有写入应用资料库或生产代码。

## 6. 验证结果

- 最后一次前端测试：**37 项通过，0 项失败**，见 测试结果（本机记录）。其中包含本轮新增的 3 项最近播放回归测试。
- Vue/TypeScript 类型检查、Vite 生产构建、macOS Release 构建完成。
- 应用签名验证通过，DMG 构建与校验通过；构建输出约 6.90 MiB，DMG 约 3.8 MiB。
- 原生应用恢复账户，读取到 **629 首收藏、4 张歌单**；恢复保存的歌曲进度并继续播放。
- 原生窗口观察到实际歌曲、随时间推进的逐字歌词及翻译。精简后的界面不再显示点击提示、音质或歌词类型标签。
- 在 960×680 和 1280×840 浏览器窗口中检查长标题、歌单筛选、导航与搜索的间距、队列弹窗和水平溢出。
- 歌词页仅显示一组播放控制；`Esc` 返回后，测试列表滚动位置由 200 保持为 200。
- 1280px 测试窗口中，封面和标题左边缘均为约 **153.6px**；浏览页进度条从窗口左侧贯穿到右侧，位于播放栏顶边。歌词页进度条位于播放按钮上方。
- 暂停打开歌词页能够绘制歌词，译文与音译开关可操作；浏览器检查未记录页面运行异常。

普通正文、次要文字、强调色在指定不透明底色上的对比度分别约为 16.1:1、5.79:1、5.34:1。此计算不等于对整个动态界面完成可访问性审查。

Intel、较旧 macOS、长时间 CPU/GPU 与内存占用尚未验证。
