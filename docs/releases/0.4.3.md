# Listener 0.4.3

歌手关注和专辑收藏改为与 QQ 音乐同步，本地 SQLite 只保留当前账户的同步缓存。

## Root Cause

原 `saved_catalog` 只读写本机 SQLite，界面的“收藏歌手”和“收藏专辑”不会出现在 QQ 音乐账户中；换一台设备或使用 QQ 客户端时看不到这些收藏。QQ 音乐对歌手使用“关注歌手”，对专辑使用“收藏专辑”，两者都不是歌单收藏。

## Modified Scope

- `favorites.rs`：读取 `music.concern.RelationList/GetFollowSingerList` 和 `music.musicasset.AlbumFavRead/CgiGetAlbumFavInfo`，分页、按 MID 去重并校验真实 ID。
- 歌手关注写入使用 `Concern.ConcernSystemServer/cgi_concern_user_v2` 的桌面端 comm；专辑收藏写入使用 `AlbumFavWrite/FavAlbum` 与 `CancelFavAlbum`，`uin` 使用当前 QQ 数字账号。
- `auth.rs`：从登录响应的 `encryptUin` 或导入 Cookie 的 `euin` 提供专辑读取所需的加密账号；专辑读取按 euin → 数字 uin → 仅 authst 依次尝试，鉴权和网络错误不降级重试。
- `lib.rs`：三个收藏命令改为真实云端读取/写入；写入后重新读取并确认目标 ID 的状态，再更新缓存。收藏操作使用独立互斥锁，账户变化时拒绝旧结果写回。
- `user_library.rs`：新增 `replace_saved_catalog`，按账户整表替换本地缓存；SQLite 不再是收藏的唯一来源。
- `CatalogView.vue`、`HomeView.vue`、`README.md`：歌手操作改为“关注歌手/已关注”，说明收藏与 QQ 同步。

## Failure Policy

读取失败直接显示 QQ 或网络错误，不把本地旧缓存冒充为云端收藏。写入返回成功但读回没有目标状态时返回 `QQ_WRITE_UNCONFIRMED`，不更新界面。MID 无效、响应缺少必要字段、分页不完整、账户切换或网络/鉴权失败都会明确失败；没有自动重试、默认成功或本地替代。

## Added Defensive Branches

- 专辑读取身份字段按真实 QQ 行为尝试加密 uin、数字 uin 和仅 authst；只在业务失败时切换，网络和鉴权错误立即返回。
- 关注列表与收藏专辑列表按 MID 去重，限制最大读取数量，空页但总数未读完时报告不完整。
- 收藏专辑的 `pubTime` 时间戳转换为 `YYYY-MM-DD`，封面字段兼容完整 URL、pmid 和缺失状态。
- 写入后用完整列表确认目标存在/不存在，而不是只相信写接口的返回码。

## Explicit Non-Changes

没有把本地收藏自动上传到 QQ，也没有把 QQ 云端数据写入其他账户。歌曲红心、歌单收藏、播放队列和下载逻辑不变；没有新增服务器或第二份凭据存储。

## Verification

- Rust 49 项测试通过、3 项真实 QQ 网络测试按原设置忽略；Clippy 所有目标以 `-D warnings` 通过。
- 前端 142 项测试通过；Vue/TypeScript 检查、生产构建通过。
- 真实账户只读：返回关注歌手和收藏专辑，未输出凭据或私人清单。
- 真实账户写入：对一位已关注歌手执行取消关注/重新关注，对一张已收藏专辑执行取消收藏/重新收藏；写接口返回 0，随后列表数量和状态恢复，验证后账户没有净变化。
- 0.4.3 已构建为 ad-hoc 签名的 macOS arm64 应用并覆盖安装；启动后 SQLite 缓存同时写入了歌手和专辑两类同步结果。
- 尚未验证其他 QQ/微信账户、离线状态、QQ 客户端同时修改后的合并行为，以及会员/地区权限差异。
