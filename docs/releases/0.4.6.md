# Listener 0.4.6

回滚 0.4.5 的自动衔接清理实验，优先恢复稳定播放。

## Root Cause

0.4.5 为消除衔接完成瞬间的短暂卡顿，同时引入了两项未经验证的改动：

1. 旧音源暂停后延迟 600 ms 才执行 `load()` 和 Web Audio 节点断开。
2. 下一首的 `playbackRate` 用 30 次 `setInterval` 从衔接速率平滑恢复到 1。

实际播放中，这两项改动导致更严重的卡死和音频中断，说明 WebKit 对延迟的媒体元素清理和连续 `playbackRate` 变更的容忍度不足。0.4.4 的即时清理和单次速率归 1 虽然可能有一次短暂顿挫，但不会持续卡死。

## Modified Scope

- `qq-automix.ts`：恢复到 0.4.4 的即时释放和单次 `playbackRate = 1`；移除延迟释放集合、速率恢复定时器及其清理逻辑。
- `player.ts`：恢复 0.4.4 的结束回调，衔接完成后立即启动下一首预加载。
- 移除 0.4.5 新增的 AutoMix 延迟释放/速率恢复测试。
- 版本提升至 0.4.6；AutoMix 代码与 0.4.4 完全一致。

## Failure Policy

恢复原有释放路径：切歌、暂停、关闭自动衔接和销毁 mixer 都会立即释放媒体与节点。没有新增吞错、重试或默认成功路径。原 0.4.4 的短暂卡顿问题仍未彻底解决，需要后续用时间戳和主线程采样定位，而不是继续猜测。
