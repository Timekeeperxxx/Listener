# Listener 0.2.5 · 译文占位与重启歌词修复

日期：2026-11-05。已安装至 `/Applications/Listener.app`。

## 1. Root Cause：原因

- QQ 的部分译文以独立的 `//` 表示没有翻译。解析器此前将它作为正常译文传给歌词组件，开启译文后就显示两个斜杠。
- 恢复上次播放时仅恢复歌曲、队列、进度及播放模式，没有调用歌词加载。音频保持未加载，所以直到点击播放才请求歌词，界面此前显示“暂无同步歌词”。

旧版原生应用中已复现第二项：上次歌曲恢复为暂停状态，打开歌词页显示“暂无同步歌词”。新增测试在修复前复现了两类失败。

## 2. Modified Scope：改动范围

- [lyrics.ts](../../src/lib/lyrics.ts#L60)：只将去除首尾空白后恰好等于 `//` 的译文置空。原文、音译、正常译文中的斜杠及时间戳保持原有处理。
- [player.ts](../../src/stores/player.ts#L134)：恢复当前歌曲后立即调用现有 `loadLyrics`，沿用歌词加载状态、后台解析及请求编号检查，不启动音频。
- [lyrics.test.ts](../../tests/lyrics.test.ts)、[player.test.ts](../../tests/player.test.ts)：新增七项回归测试，覆盖逐行/逐字占位符、保留真实斜杠、暂停加载、失败可见、关闭不等待歌词网络请求、切歌与账户重置隔离，以及没有当前歌曲的队列。
- npm、Cargo、Tauri 和设置界面的版本号同步为 0.2.5。

## 3. Failure Policy：失败处理

歌词网络或解析失败沿用“歌词加载失败”和重试入口，不伪装为无歌词。歌词失败与播放状态恢复失败保持独立。恢复歌曲不请求音频地址、不自动播放、不记录一次播放；退出保存也不等待歌词网络请求。

## 4. Added Defensive Branches：新增分支依据

- `key === 'translatedLyric' && text.trim() === '//'`：针对已复现的 QQ 无译文占位符；仅处理完整占位内容，测试确认 `AC/DC` 原文和含 `/`、`//` 的真实译文不受影响。
- `if (current.value)`：已保存的队列允许没有当前歌曲。只有实际恢复了当前歌曲才加载歌词，测试覆盖该情况。
- 未增加新的 `try/catch`、默认成功结果、网络重试、备用来源或兼容分支。歌词失败处理和异步请求隔离均复用已有实现。

## 5. Explicit Non-Changes：未变更范围

未修改 QQ 登录、用户资料、收藏和歌单、音频源、下载或数据库结构；未增加配置项。未改歌词逐字高亮、滚动、动画和界面布局。

按现有部署授权更新了本机 macOS 应用，保留旧版 ZIP 和应用备份；没有发布外网网站或更改云端数据。

## 6. Verification：验证

- 修复前聚焦测试为 6 项失败、26 项通过，失败分别来自译文占位符和恢复时未请求歌词；修复后全部 70 项前端测试通过。
- `npm run build` 通过 TypeScript 检查和前端构建；`npm run mac:build` 通过发布构建，生成 arm64 应用与 DMG。
- 安装版 Info.plist 显示 0.2.5；`codesign --verify --deep --strict` 通过；安装后的可执行文件 SHA-256 与构建产物一致；DMG 校验通过，旧版 ZIP 完整性检查通过。
- 原生应用实际重启后，在没有点击播放的状态打开歌词页：当前歌曲《The Hills (Explicit)》停在 45.2 秒，按钮提示“继续上次播放”，进度条仍禁用，译文开启，歌词已显示。该状态区别于播放后再暂停。
