# Listener 0.5.2

修复点击歌词跳转后歌词与音乐不同步。

## Root Cause

有两个问题叠加：

1. `SyncedLyrics` 每帧调用 AMLL 的 `setCurrentTime(time)` 时没有传 `isSeek = true`。点击歌词造成时间大幅跳转后，AMLL 仍按普通播放推进处理，自动滚动对齐可能保持挂起；视图没有重置到目标行。
2. WebKit 的 `HTMLMediaElement.currentTime` 赋值是异步生效的。`seek()` 赋值后立即读取 `audio.currentTime` 仍是旧位置，歌词帧会先用旧时间覆盖点击目标，直到 `seeked` 事件到达。

另外，点击歌词没有扣除当前歌词偏移，存在偏移时目标行也会错位。

## Modified Scope

- `player.ts`：新增临时 seek 目标；`seek()` 立即把界面与歌词时钟放到目标位置，`seeked` 事件或 1.2 秒超时后恢复正常媒体时钟；换歌和重置时清除。
- `SyncedLyrics.vue`：新增 `syncTo()`，在点击跳转时使用 `setCurrentTime(time, true)` 并 `resetScroll()`，让 AMLL 立即按跳转处理并回中。
- `LyricsView.vue`：点击歌词时扣除全局及本首歌词偏移后再 seek，并把目标行时间同步给 AMLL。
- 新增一条回归测试，验证媒体 seek 尚未完成时歌词时钟仍停留在请求位置。

## Failure Policy

没有改变音频 seek 本身或 QQ 音源逻辑；媒体未加载时仍不执行 seek。超时只清除临时显示目标，不伪造新的播放位置；真实 `seeked` 后继续使用媒体时钟。

## Verification

- 前端 143 项测试通过，含新增 seek 目标测试；Vue/TypeScript 检查和生产构建通过。
- Rust 49 项测试、Clippy 通过。
- 实际歌词点击的听感与滚动对齐仍需在安装后的原生窗口中确认。
