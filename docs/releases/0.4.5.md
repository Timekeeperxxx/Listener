# Listener 0.4.5

修复 QQ 自动衔接完成、下一首完全接管的瞬间出现的卡顿。

## Root Cause

`QqAutoMix.fade` 的结束定时器在衔接完成的那一帧同时做了三件重活：

1. `finish()` 立即对旧音源执行 `pause()`、`removeAttribute('src')`、`load()`，并断开它的 `MediaElementAudioSourceNode`、滤波器和增益节点。WebKit 的 `load()` 和音频图重建是同步主线程操作，正好落在衔接点。
2. `blendTo` 的结束回调立即调用 `prepareNext()`，开始读取下一首音源并创建新的音频元素和 Web Audio 节点图。
3. `finish()` 把下一首的 `playbackRate` 从衔接速率直接改为 `1`；3%–20% 的速率跳变在切点会被听成一次顿挫。

## Modified Scope

- `qq-automix.ts`：旧音源先立即 `pause()`，但 `load()`、断开节点和删除 deck 延迟 600 ms，避开切点；`dispose()` 会清理待释放定时器。
- `qq-automix.ts`：下一首的 `playbackRate` 用 30 次、每次 100 ms 的步进在 3 秒内平滑回到 `1`，不再瞬间跳变。
- `player.ts`：衔接结束只清空 `mixMode`；下一首的预加载交给随后到来的 `timeupdate`，不再在切点启动新的音源请求和音频图。
- `tests/automix.test.ts`：新增 2 项回归测试，覆盖延迟释放和速率恢复。

## Failure Policy

延迟释放只延后资源回收，不改变音频输出和账户状态；切歌、暂停、关闭自动衔接或销毁 mixer 时仍会立即释放。没有把失败吞掉，也没有伪造成功状态。速率恢复定时器在 deck 被释放或 mixer 销毁时停止。
