# Listener 0.5.3

修复开启自动衔接后，点击歌词跳转时声音明显晚到的问题。

## Root Cause

开启自动衔接时，当前播放的 `HTMLAudioElement` 被接入 `MediaElementAudioSourceNode`，所有声音都经过 Web Audio 图。关闭自动衔接后同一操作不延迟，确认问题是 Web Audio 媒体源路径：WebKit 在这条路径上 seek 需要重新缓冲，导致歌词已经跳到目标行、声音过一会儿才到。它与此前修复的歌词时钟/滚动无关。

## Modified Scope

- `qq-automix.ts`：自动衔接不再创建 AudioContext、MediaElementAudioSourceNode、滤波器和增益节点；改为直接调整两路 `HTMLAudioElement.volume`，按 QQ 的切点、过渡时长和增益曲线交叉淡化。
- `player.ts`：衔接开始时把下一首音量设为 0，由直接音量曲线淡入；不再依赖 Web Audio 的静音/增益节点。
- 保留点击歌词的 seek 目标、AMLL `isSeek` 和滚动重置；保留 QQ 的切点与过渡时长。
- `tests/automix-volume.test.ts`：新增直接音量淡化和旧音源释放测试。

## Tradeoff

自动衔接失去原来的低通滤波和低频搁架效果，只保留音量交叉淡化。这样换取普通播放和歌词跳转不经过 Web Audio，seek 不再被媒体源缓冲拖慢。当前本来就不做节拍变速，切点和淡化时长保持不变。

- Rust 49 项测试、Clippy 通过。
- 0.5.3 已构建并覆盖安装；实际听感和歌词点击后的 seek 延迟仍需在原生窗口确认。
